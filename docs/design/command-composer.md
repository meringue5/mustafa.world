# Command Composer Design

## 핵심 원칙

커맨드 컴포저는 일반적인 다음 토큰 예측기가 아니다.

표면 텍스트만 보고 다음에 올 한국어 단어를 추측하는 LLM 흉내를 내지 않는다. 컴포저는 현재 세계 상태가 허용하는 행동을 보여줘야 한다.

설계의 중심은 다음이다.

```text
보이는 세계 상태 -> 가능한 affordance -> 커맨드 후보
```

다음이 아니다.

```text
이전 텍스트 -> 그럴듯한 다음 토큰
```

## 후보 생성 경계

후보 추천은 확정된 입력이 공백으로 끝나는 단어 경계에서만 열린다. 한글 IME 조합 중인 글자를 미리 읽어 토큰을 추정하지 않는다.

-   `가`: 후보 없음
-   `가 `: `어디로?`와 장소 후보 표시
-   `노아`: 후보 없음
-   `노아 `: 현재 세계 상태에 맞는 대상 기반 후보 표시

사용자가 공백을 입력하면 그 단어가 완성되었다고 보고, 그때부터 세계 상태 기반 후보를 계산한다.

## 동사 먼저 입력

동사 먼저 입력은 가장 명확한 경로다. 동사는 함수처럼 시그니처를 가진다.

예시:

```text
가(destination)
먹다(object: edible)
주다(object, recipient)
쓰다듬다(target: touchable actor)
살펴보다(target?)
기다리다()
```

사용자가 동사를 입력하면, 컴포저는 해당 동사의 시그니처를 활성화하고 비어 있는 슬롯을 묻는다.

예시:

```text
가 
어디로? 거실  서재 베란다
```

```text
먹어 
무엇을? 과자  사과
```

필수 슬롯이 여러 개인 동사는 여러 빈 슬롯을 후보줄에 함께 드러낼 수 있다. 그래도 각 후보는 현재 세계 상태에서 나온 것이어야 한다.

예시:

```text
줘 
무엇을? 츄르  과자    누구에게? 노아
```

## 명사 먼저 입력

명사 먼저 입력은 기본적으로 조사 후보로 시작하지 않는다.

초기 프로토타입은 다음과 같은 후보를 제안했다.

```text
노아? 노아를  노아에게  노아와
```

이 방식은 한국어 파싱에는 편하지만, 의미 있는 행동을 보여주기 전에 다음 토큰을 맞히는 UI처럼 느껴진다.

권장 방향은 affordance 우선이다.

```text
노아
쓰다듬어  불러  살펴봐  츄르를 줘
```

필요하면 격 역할별로 묶어서 보여줄 수 있다.

```text
노아를: 쓰다듬어  살펴봐
노아에게: 츄르를 줘
노아와: 놀아
```

조사는 여전히 파서에 중요하다. 하지만 조사는 보통 내부 역할 표식이어야 하며, 기본 UI가 플레이어에게 먼저 강요하는 선택지가 되어서는 안 된다.

## Affordance 원천

후보는 명시적 세계 데이터와 현재 맥락에서 생성한다.

-   현재 장소의 링크
-   보이는 행위자
-   보이는 사물
-   인벤토리
-   `edible`, `portable`, `giftable` 같은 사물 태그
-   `touchable`, `hostile`, `asleep` 같은 행위자 태그
-   플레이어, 행위자, 아이템, 장소 사이의 알려진 관계
-   최근 언급된 보이는 엔티티

숨겨진 퍼즐 해법이나 아직 발견하지 못한 상호작용은 후보로 보여주지 않는다.

## 온톨로지 방향

월드가 커지면 사물과 행위자의 관계를 가벼운 온톨로지로 옮긴다.

예시:

```text
노아 is actor
노아 has tag touchable
노아 likes 츄르
츄르 is item
츄르 has tag giftable
player has 츄르
```

여기서 컴포저는 다음 affordance를 도출할 수 있다.

```text
노아 -> 쓰다듬어
노아 + 츄르 -> 츄르를 줘
츄르 -> 먹어 / 줘 / 살펴봐
```

이 방식은 여전히 결정적이고 검토 가능하다. 규칙의 원천은 통계적 언어 예측이 아니라 세계 데이터다.

## 리서치 메모

이 설계는 다음 영역과 겹친다.

-   interactive fiction command grammar
-   MUD verb/object parser
-   affordance-based UI
-   entity-component system
-   lightweight game ontology
-   planning/action schema

파서를 더 똑똑하게 만들기 전에 LLM식 텍스트 완성보다 이 영역을 먼저 조사한다.
